# ADR-002: Separate Consensus Evidence from Runtime Metadata

## Status
Accepted

## Context
During initial replay testing (Sprint 1.5), execution transcripts failed determinism verification due to variances in the `relative_time_ms` property. This property, which depends on real-world execution speed (measured via wall-clock/CPU timers), fluctuates across runs and between different systems.

If the entire transcript were to participate in consensus hashing, honest validators would produce different hashes for the same executing asset, causing consensus failures.

## Decision
We split the `BehaviorTranscript` into two logical layers:
1. **Evidence Layer (`Event`)**: Contains strictly consensus-critical, deterministic attributes (e.g. sequence, sensor name, event type, and payload content like file hashes).
2. **Metadata Layer (`RuntimeEventMetadata`)**: Contains node-local, nondeterministic information (e.g., `relative_time_ms`).

The `TranscriptSerializer` is modified to only serialize the Evidence Layer (`canonical_dict()`).

## Consequences
- **100% Deterministic Consensus**: The serialized output of the transcript is identical across multiple runs and different host environments.
- **Retained Diagnostics**: Wall-clock performance and other telemetry continue to be captured for debugging and monitoring purposes without impacting consensus.
