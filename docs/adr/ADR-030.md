# ADR-030: Multi-Format Runner Strategy

## Status
Accepted

## Decision
Nebula v1.1.0 extends sandbox execution to support multiple interpreted
runtime environments through dedicated `Runner` subclasses:

- `JavaScriptRunner` — executes `.js`, `.ts`, `.mjs` files via Node.js
- `ShellRunner`      — executes `.sh`, `.bash`, `.ps1`, `.bat` via platform interpreter
- `JavaRunner`       — executes `.jar`, `.class` files via JVM
- `ArchiveRunner`    — unpacks `.zip`, `.tar`, `.gz`, `.tgz` and recursively
                        applies `NebulaVerifier` to each extracted asset

## Rationale
All new runners share the same isolation model as `PythonRunner`:
workspace containment, read-only asset copy, environment whitelist,
and timeout enforcement. No new architectural concepts are needed.

## Classification Expansion
`ClassificationEngine._category_from_extension()` was extended to map
22 additional extension groups across SCRIPT, IMAGE, DOCUMENT, AUDIO,
VIDEO, ARCHIVE, and DATA categories.

## Policy Expansion
`ExecutionPolicyEngine` now routes AUDIO, VIDEO, and DATA assets to
static-only (`COMPLETE`) evaluation, and ARCHIVE to `CONTINUE`
(handled by ArchiveRunner).

## Boundary
Native compiled binaries (`.exe`, ELF, Mach-O), mobile packages (APK/IPA),
and Office macros remain outside the execution scope of this design.
This boundary is structural and intentional.
